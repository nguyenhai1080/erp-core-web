# Output reconciliation PDF reading and identity workspace — v0.6.17

Builds on v0.6.16 intake. Runtime reads original PDF text, falls back to local English OCR per scanned page, retains raw text/provenance, displays extracted header metadata and checks selected service/month and candidate contract. It does **not** parse or approve financial table details, stamp PDF, create revenue or supersede a financial chain. Green MATCHED means service/month match only, never final approval.

## Source grounding

Exact donor Apps Script deployment v61. `21_Recon_OCR.js` DGC_extractMovitelReconPeriodV8124_ and DGC_extractMovitelReconServiceV8124_ (147–235), DGC_parseMovitelReconText_ header fields (334), DGC_inferServiceFromAgreement_ (1524), DGC_parseMovitelReconIdentityV81185_ (2307). `20_Recon_Core.js` normalized service identity (582), parseMovitelReconPdfTextV81185_ (379): persist raw source, full-read identity, precommit duplicate/payment checks, keep candidate separate from final import. `22_Recon_PDF_Approval.js` getReconPdfReviewDataJson (45): original/PDF metadata, raw OCR, warnings and rebuilt child/summary rows. `04_DataAccess_Utils.js` DGC_normName_, DGC_matchServiceId_, DGC_matchContractId_. Donor is read-only, never executed; source hashes in DGC_SOURCE_INVENTORY.json.

Characterization preserves current/historical title and Service-label preference; a longer dedicated label can extend a truncated title, an unrelated REPUBLIC OF MOZAMBIQUE label cannot override it. Historical MOVTV SERVICE title, split-line Service label, named/numeric Period/Month and historical in-month sentence are supported. Header period takes priority over signature dates. Two-digit years map 2000–2099; allowed years 2000–2100. Agreement fallback uses its final slash/hyphen segment and displays a warning. PDF title/service normalization handles spaced/hyphen/underscore IDs. Header exchange rate and DIGICOM total USD follow donor labels, stored as exact Decimal strings; these values remain unverified and no arithmetic is applied.

## Explicit adaptations and remaining parity

Donor uses Drive/Google Docs OCR. Target uses Poppler and Tesseract inside the existing API container, without sending PDF bytes to another OCR service. Docker installs official Debian poppler-utils/tesseract-ocr/English data. Command syntax follows [Tesseract documentation](https://tesseract-ocr.github.io/tessdoc/Command-Line-Usage.html). Each page is inspected independently, so a text cover does not bypass a later scanned page. A user can request force-OCR if the embedded text layer is misleading. OCR accuracy is not assumed from the presence of text.

Service resolution uses unique exact canonical aliases from immutable serviceKey, editable code, name and keyword in the same company. This adapts donor exact normalized matching but deliberately does not guess a first substring/child-service match or apply donor hardcoded legacy-ID fallbacks. Alias ambiguity blocks MATCHED. Distinct identities across pages are flagged. Matching uses current catalog values on each detail request, so changed aliases cannot leave an old green result authoritative.

Contract candidates require same-company partner, Output/Active, period-effective and active service link, plus normalized exact Contract_No matching Agreement_No. No first-candidate selection or donor fallback that could choose a wrong partner is used. A match does not bind a financial contract. Partner/company identity printed in the document is not verified by this release; selected company/partner context is preserved, never overwritten with hardcoded DIGICOM/MOVITEL values.

The full donor grouped/column-major child-service, historical MOVTV financial invariants, MZN/USD summary reconciliation, tax/WHT/FX arithmetic and aggregate-detail safeguards remain to be ported before financial validation. Identity source JSON explicitly keeps identityVerified=false and financialDataVerified=false until that reviewed workflow exists. Reading mismatch retains the original selection/business key and reports UNDER_REVIEW rather than moving records silently. Reading a source with InvoiceScope dependencies reports the existing financial block and never edits Invoice/revenue/recon state. Replacement behavior remains v0.6.16 intake-only protection.

## Storage, access and failure behavior

Additive migration adds nullable raw_text/extraction_data/read_at to existing intake rows; no existing GST records are converted or imported. Detail requires RECON_VIEW. Reading requires RECON_UPLOAD and RECON_VIEW plus Origin/CSRF, expected version and eligible source state UPLOADED/OCR_EXTRACTED/UNDER_REVIEW. Original path/company/size/SHA256 verified before extraction and again before committing. Row lock/version check prevents overwriting newer results. UPLOADED becomes OCR_EXTRACTED only for service/month match; otherwise UNDER_REVIEW. No VALIDATED/APPROVED transition is exposed.

Raw text is available only in scoped detail, omitted from list and audit. Audit stores actor, metadata, checksum, status and parsed identity; no PDF bytes or raw text. Last successful read is retained on command failure. Re-reading creates another audit snapshot; concurrent reading within one API process returns 429. Shell-free argument arrays, private unique temp directory, one worker, one Tesseract thread, 12-page limit, 200000-character result limit, bounded child output, 30-second subprocess limit and 90-second total budget prevent unbounded reading. Temporary files are removed in finally. Encrypted, broken, too-large/page-count or unreadable files fail clearly. Native-tool paths can be overridden by trusted server environment PDFINFO_BIN/PDFTOTEXT_BIN/PDFTOPPM_BIN/TESSERACT_BIN; these are never accepted from requests.

UI and same-origin proxy allow 120 seconds for the bounded read operation, retaining the ordinary JSON request-size limit. The modal cannot close while a read is pending. Source/metadata review controls use existing permissions, with no new grants or credentials.
